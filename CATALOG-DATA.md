# Подключение товарной выгрузки

Сейчас каталог содержит ноль реальных товаров. 18 подписанных заглушек — места под будущие карточки. Поиск и фильтры не выдают заглушки за реальные товары.

Категория ограничивает показываемые заглушки. Если указан запрос, артикул или производитель, вместо вымышленных совпадений появляется сообщение о наполнении каталога. После внесения данных работают общая фильтрация, число результатов и пагинация по 12 товаров. Параметры сохраняются в URL. Сброс очищает все фильтры. Переходы с главной по catalog.html#filters и другим категориям поддерживаются.

Данные читаются из assets/js/catalog-data.js без fetch и без сервера. Именно поэтому HTML можно открыть двойным щелчком. Структура будущей записи:

```js
{
  id: 'устойчивый ID из выгрузки',
  name: 'Название из базы',
  article: 'Артикул из базы',
  manufacturer: 'Производитель детали',
  category: 'filters',
  description: 'Описание из базы',
  image: 'assets/images/products/имя-файла.webp',
  url: 'страница-товара.html'
}
```

Это схема, а не реальный товар. Не заменяйте артикул нулём или выдуманным значением. Отсутствующие сведения оставляйте пустыми до проверки. category должна совпадать с ID справочника; manufacturer обозначает производителя детали, а не автоматически марку машины. Список производителей деталей взят из доступного старого сайта; товары этих производителей не заявляются в наличии.

В WordPress эти данные будут приходить из выбранной системы каталога, а серверная фильтрация и пагинация заменят статический механизм. Для большого каталога не следует отдавать весь массив товаров браузеру. Текущая реализация — работающая основа интерфейса для согласования и локального прототипа.

Проверка логики без изменения данных сайта:

```text
node --test checks/catalog-filter.test.cjs
```

Тестовые записи существуют только внутри теста и на сайт не подключены.
